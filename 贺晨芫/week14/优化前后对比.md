# 抖音巨量算数采集 Skill — 优化前后对比

> 本文档说明本 Skill 从「浏览器自动化爬取」到「直连 API + AES 解密」，再到「本次效率 / 可靠性优化」的进化过程，并量化本次优化的收益。
> 文中效率数值为**基于算法行为的理论估算**（非实测基准），用于体现量级差异。

## 一、能力进化时间线

| 阶段 | 采集方案 | 鉴权方式 | 输出 | 主要短板 |
|------|----------|----------|------|----------|
| ① 浏览器拦截 (scraper.py) | DrissionPage 拦截页面请求 | 无（页面级） | — | 依赖浏览器、速度慢、难定时 / 云端 |
| ② 直连 API + AES v1 (juliang_collector / fetch_direct) | requests 直连后端接口 | msToken+X-Bogus / sessionid | CSV 覆盖 或 xlsx 增量 | 每次全量 180 天、仅串行、无重试 |
| ③ 直连 API + AES v2（本次优化 Skill） | requests 直连 + AES + 增量 + 并发 + 重试 | msToken+X-Bogus | xlsx 增量去重 | 已补齐效率与可靠性短板 |

## 二、本次优化（② → ③）核心变化

| 维度 | 优化前 (v1) | 优化后 (v2) | 收益 |
|------|-------------|-------------|------|
| 采集窗口 | 每次固定全量 180 天 | `state.json` 记录最新日期，仅拉增量（上次末日+1 ~ 今天） | 重复运行解密量下降约 180× |
| 并发能力 | 仅串行 | `--concurrency N` 线程池并发，首跑可提速 | 首跑最高约 N× 提速（需控频防风控） |
| X-Bogus 生成 | 每次请求 `new XBogus()` | 模块级单例复用 | 减少重复实例化开销 |
| 失败处理 | 网络抖动 / 5xx 直接丢批次 | 指数退避重试（默认 3 次） | 瞬态错误自愈，减少人工重跑 |
| 风控识别 | 未专门处理 | 识别非 JSON 风控页并直接报错（不重试，提示换 Cookie） | 失败原因清晰 |
| 进度 / 跳过 | 简单打印 | `[i/n]` 进度 + 已最新词 `⊘ 跳过` | 可观测性更好 |
| 输出稳定性 | 跟随运行目录飘移 | 固定 `output/keyword_index.xlsx` + `state.json` 原子写回 | 不易丢数据、易定位 |

## 三、执行效率对比（估算模型）

**假设**：50 个关键词；`HISTORY_DAYS=180`；日调度（每天跑一次）；优化后每日仅补 1 天增量。

| 指标 | 优化前 (v1) | 优化后 (v2) | 变化 |
|------|-------------|-------------|------|
| 单次运行采集历史天数 | 180 天 | 1 天 | 下降 99.4% |
| 单次解密数据行数 | 50 × 180 = 9000 行 | 50 × 1 = 50 行 | 约 180× 更少 |
| 月度累计解密行数（30 次） | 270,000 行 | 50×180(首跑) + 50×29 = 9,850 行 | 约 96% 更少 |
| 首跑耗时（默认串行） | 基准 1× | 基准 1×（并发可降） | 视并发数而定 |
| 瞬态失败恢复 | 需人工重跑 | 自动重试 | 运维介入下降 |

> 说明：首次运行 v2 仍为全量 180 天；增量收益在「第二次及以后」体现。实际值受关键词数量、接口响应、网络环境影响。

## 四、Token 消耗说明（诚实视角）

- **运行时：0 LLM Token。** 本 Skill 是纯本地 Python 脚本，执行过程不调用任何大模型，不产生 token 费用。
- **进化意义**：早期若依赖「浏览器自动化 / Agent 反复手动重跑」完成采集，每次运行都隐含算力与人力成本；本 Skill 将其固化为**确定性增量脚本**（自带重试 + 断点续采），把"每次全量重算"的隐性成本压缩到接近 0。
- **构建成本**：Skill 本身的开发 / 迭代是一次性的（本次优化即在既有脚本上增量改造，未重写），后续复用无边际成本。

## 五、结论

本次优化在不改变「直连 API + AES 解密」核心方案的前提下，把 Skill 从"能用"提升到"好用、可长期定时运行"：

- **效率**：重复运行数据量下降约 180×；
- **可靠性**：瞬态错误自愈、断点续采、风控可识别；
- **可维护性**：固定路径、原子写回、参数化并发 / 重试。
